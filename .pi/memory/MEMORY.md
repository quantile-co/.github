**#decision** [[org-factory-terraform-migration]]
The proposed `.github` Terraform root consumes the unchanged, immutable-revision Factory project modules. Preserve this repository's existing Cloud Storage bucket and `repository/prod` backend. The Day 0 runbook in `tf/README.md` is historical and must not be rerun. `tf/infrastructure/moved.tf` covers all 13 existing managed resources: the repository, state infrastructure, environments, and the build branch policy. The aliased GitHub provider keeps the old state binding. These moves and the alias are temporary migration scaffolding. Remove them in a later reviewed change only after a separately authorized production Apply and state/provider verification. Plan/Apply keep protected main, maintainer, workload identity federation, environment, and backend-lock guards. Credentials remain runtime-only. The Factory module intentionally replaces the old merge/review restrictions with signed linear history and disables repository auto-merge. Retire the old Dependabot auto-merge workflow before applying that policy. Preserve the build environment and its cache-secret boundary. Local backend-free checks pass, but no production Plan or Apply has run. The user wants a new accurate Day 0 runbook only after migration, without old-code or migration instructions. Leave `tf/README.md` untouched until that phase. The separate build environment still guards the existing main-only Cachix write secret. A single-prod environment design must first replace Build and migrate its secret without widening untrusted access.
